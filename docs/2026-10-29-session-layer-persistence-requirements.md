# dsh-prompt-library 0.2 需求档：会话系统层持久化

> 三句话：系统提示词层不再随 DSH 重启消失；每个会话的 1~3 条层存在**这个会话自己的文件夹**里，本插件只负责这一处的读写，不与其他插件耦合；浏览器刷新后标签自己回来；任何读失败先试备份/兜底，都失败才按“没有这个文件”的原始会话回退；单会话新增开销不超过 100ms。
>
> 文档定位：本档是 0.1 需求档（[requirements.md](requirements.md)，2026-10-29 as-of）的增量，覆盖其中 S6、FR-6、非目标第 5 条、AC-7 的语义变化。两者冲突时，0.2 范围以本档为准。

## 1. 背景

- 0.1 是刻意不落盘的：系统层只存在 DSH 进程内存里，重启即清空，理由写在 [requirements.md](requirements.md)（S6、非目标、AC-7）和 [design.md](design.md)（§2 非目标、§5.3、§9、§12.3）——避免“看不见的持续计费”。
- 用户实测有两个丢失场景：
  1. 重启 DSH：层和标签一起消失。这是 0.1 的设计，不是 bug。
  2. 只刷新页面：标签也消失，但宿主里的层其实还在。这是恢复链路的时序缺口（根因与证据见设计档 §1.2）。
- 用户裁决（2026-10-29）：
  - 接受“重启后自动恢复注入、继续每轮计费”；不想要时自己点标签上的 ×。
  - 不加“已恢复”之类的额外字样，标签和总 token 本身就是提示。
  - 层文件要存在**会话自己的文件夹**里，而不是插件的全局目录；本插件只负责“写到这个位置、从这个位置读”，不与其他插件约定。
  - 先看需求档和设计档，确认后走工程模式实施。

## 2. 用户与场景

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| S1 | 重启恢复 | 重启 DSH 后打开旧会话：标签还在，系统提示词里仍有这几段正文。 |
| S2 | 刷新恢复 | 浏览器刷新后，当前会话的标签直接回来，不依赖“后台刚好扫到”。 |
| S3 | 关闭 | 点某条标签的 × 后，标签消失；再次重启也不会回来。 |
| S4 | 多会话隔离 | A 会话的层不影响 B 会话；两边各自重启后互不串。 |
| S5 | 文件归属 | 层文件写在该会话自己的文件夹里；读取也从同一个位置来；不依赖其他插件。 |
| S6 | 损坏与失败 | 层文件不存在、格式错、字段错、超大、不可读、读取中被删：会话照常加载，侧边栏照常显示；备份/兜底可读时自动恢复；都不可用才按无层显示、注入为空；不抛错、不写盘、不阻塞；写盘失败同样不产生假标签。 |
| S7 | 空会话 | 新会话还没有自己的文件夹时也能加层；文件夹出现后自动搬进去。 |
| S8 | 升级 | 从 0.1 升到 0.2：0.1 本来就没有落盘的层，不需要升级迁移；库和现有行为不变。 |
| S9 | 加载开销 | 打开或使用会话时，本插件新增耗时不超过几十到 100ms；不扫描全部会话；坏/超大文件不读取、不解析、不反复重试。 |

## 3. 目标与非目标

### 目标

- 每个会话的 1~3 条系统层，写入该会话自己的文件夹；读取也从那里来；本插件不与其他插件约定。
- DSH 重启后，第一次使用该会话时自动读回；系统提示词注入与界面标签同时恢复。
- 浏览器刷新后，标签区域主动读取本会话的层，不再只靠一次后台扫描。
- 写入先落盘、成功后才更新内存和界面；失败时明确报错。
- 单文件损坏、备份损坏、目录缺失、写盘失败都有确定行为，不阻塞启动。
- 读失败先试备份/兜底；都失败才按“没有这个持久化文件”的原始会话回退：不抛错、不写盘、不影响会话和侧边栏。
- 单会话首次读取新增耗时 p95 ≤ 100ms、典型 ≤ 20ms；不扫描全部会话；超大文件不读取解析。
- 最多 3 条、同 id 更新、顺序、token 估算、菜单、设置页、编辑弹窗都不变。
- 不加“已恢复”字样，不新增全局开关或逐条开关。

### 非目标

- 不做全局常驻注入；没有层时系统提示词仍然零新增 token。
- 不做云同步、跨机器同步、团队共享。
- 不与其他插件约定文件搬移、同步；本插件只认会话目录里的文件。
- 不做 0.1 内存层到 0.2 的升级迁移（0.1 没有可迁移的持久数据）。
- 不自动清理旧会话的层文件（文件跟会话目录走；目录没了就按无层处理）。
- 不改变“最多 3 条”的产品上限，也不做“每条单独选择是否保存”。

## 4. 功能需求

| 编号 | 需求 | 说明 | 验收要点 |
| --- | --- | --- | --- |
| FR-1 | 存储位置 | 每个会话的层写进该会话自己的文件夹，使用固定文件名；另存一份上一版备份（主文件坏时自动恢复）。不放在插件全局目录（FR-6 的兜底文件除外）。 | 会话文件夹里能看到层文件；插件全局 sessions/ 目录在正常会话下不新增文件。 |
| FR-2 | 读取与恢复 | 会话第一次被使用（组装系统提示词或界面请求标签）时读取；文件变化后重读；重启后自动恢复注入与标签。 | 重启后 S1/S4 通过；同一进程内文件被外部改动后，下一次读取能看到新内容。 |
| FR-3 | 写入与失败 | 加/改/删层时，先读成功再写盘；写盘成功后才更新内存与界面。I/O 类读失败（stat/read 异常、不可读、读取中被删）且所有副本都不可用时拒绝写入（layer-read-failed），不用空内存覆盖磁盘；混合情形按 I/O 优先：只要出现过 I/O 错误且无可用命中就拒绝写入；内容类覆盖只在没有任何 I/O 错误时允许；内容类失败（格式/字段/超大/非普通文件）且无可用副本时允许写新文件覆盖坏主文件（把坏文件修回来）；写失败返回错误；界面不出现新标签，内存不留半截。 | I/O 读失败/写失败：返回错误、标签不变、磁盘不被覆盖；内容类失败无副本：允许加层覆盖坏文件。 |
| FR-4 | 刷新恢复 | 标签区域出现时主动请求本会话的层；同一会话的并发请求合并；失败可重试。 | 刷新后不依赖会话列表变化，标签直接回来；连续两次 ensure 只发一次读。 |
| FR-5 | 文件归属与加载 | 写入会话目录；从会话目录加载；目录不存在时按无层处理；不依赖其他插件。 | 会话目录里有文件；重启后从那里读回；不依赖插件全局目录（兜底除外）。 |
| FR-6 | 空会话兜底 | 会话文件夹不存在时，先写插件目录下的兜底文件；文件夹出现后自动搬入并删除兜底文件。 | 新会话加层不报错；文件夹出现后文件搬入，兜底文件消失。 |
| FR-7 | 读失败回退 | 读失败（不存在、格式错、字段错、超大、不可读、读取中被删、不是普通文件）按顺序尝试备份/兜底：可读就用；都失败才按“没有这个持久化文件”处理（标签空、注入空）。I/O 类失败且所有副本都不可用时拒绝写入；混合情形按 I/O 优先；内容类失败且无可用副本时允许加层写新文件覆盖（仅在没有任何 I/O 错误时）。全程不抛错、不写盘、不改名。 | 坏文件不被改名、不写盘；会话与侧边栏正常；备份/兜底可读时恢复；都不可用时按无层显示；I/O 类加层被拒。 |
| FR-8 | 安全 | 会话编号只接受字母、数字、点、下划线、短横线（与平台会话 id 形状一致）；文件名固定，不把用户可控字符串直接拼进路径。 | 含斜杠、双点、空格的编号不产生越界写入；错误可读。 |
| FR-9 | 上限与语义 | 最多 3 条；同 promptId 更新原位置；顺序按加入顺序；token 每次重算；无层时系统段为空串。 | 第 4 条仍被拒绝；同 id 不新增行；空会话的系统段为空。 |
| FR-10 | 可见性与开关 | 不加“已恢复”字样；不新增保存开关；标签与总 token 的现有展示不变。 | 重启后标签外观与 0.1 一致，只多了“它还在”。 |
| FR-11 | 导出边界 | 本批不把层文件纳入导出/换机流程；换机后需要重新加层，文档写明。 | 文档有明确边界说明；不假装层会跟着导出。 |
| FR-12 | 加载开销 | 单会话首次读取新增耗时 p95 ≤ 100ms、典型 ≤ 20ms；不扫描全部会话；文件超过 1 MiB 不读取不解析；重复读取只做 stat，不重复解析。 | 性能测试：有效文件首读 < 100ms；10 MiB 文件不读取；重复读取不再次解析。 |

## 5. 非功能需求

- **性能**：启动时不做全量会话扫描；单次读取只碰当前会话的目录。单会话首次读取新增耗时 p95 ≤ 100ms、典型 ≤ 20ms；重复读取只做 stat、不重复解析；单文件超过 1 MiB 不读取、不解析；坏文件不反复重试（按 stamp/退避）。
- **可靠性**：原子替换（临时文件写完再改名）；一份上一版备份（主文件坏时自动恢复）；读失败先试备份/兜底，都失败才按无文件回退；不抛错、不写盘、不影响会话/侧边栏；写失败不产生假标签。
- **安全**：纯本地、不联网；编号白名单；固定文件名；日志只记会话 id、路径、错误码，不记正文。
- **兼容**：DSH 0.2.1-rc.x；Windows 优先，兼容 macOS/Linux；会话目录布局按设计档 §1.3 的平台事实处理，布局变化时有兜底。
- **读路径零副作用**：读失败不隔离、不改名、不清理、不写盘；只有用户显式加/删层才写。
- **可逆**：用户点 × 即写空状态；文件也可手工删除；删除后该会话按无层处理。
- **可观测**：读/写/隔离失败写 host 日志（带会话 id 与路径），不打断会话。

## 6. 验收标准

| 编号 | 验收点 | 检查方式 |
| --- | --- | --- |
| AC-1 | 加一条层 → 关闭 DSH → 重启 → 打开同一会话：标签在，系统提示词含该正文。 | 手工 + host 单测（新实例读回） |
| AC-2 | 重启后点 × → 再重启：标签不在，系统段为空。 | 手工 + 单测（空状态写回） |
| AC-3 | 浏览器刷新：标签还在，且不依赖会话列表再次变化。 | 手工 + 客户端单测（挂载即读、并发合并） |
| AC-4 | 两个会话各加不同层：重启后互不串。 | 单测 + 手工 |
| AC-5 | 把整个会话目录复制到别处再复制回来（不启动任何其他插件）：层文件仍在，读回一致。 | 单测（临时目录复制） |
| AC-6 | 主文件写成坏 JSON：启动不报错；备份好时自动恢复备份；备份也不可用时再试兜底；都不可用才按无层处理，不改名、不写盘；此时加层允许写新文件覆盖坏主文件（修复）。 | 单测 |
| AC-7 | 模拟写盘失败：加层返回错误，界面不出现新标签，内存/磁盘保持旧状态。 | 单测 |
| AC-8 | 会话文件夹不存在时加层：兜底文件存在；文件夹出现后自动搬入并删除兜底文件。 | 单测 |
| AC-9 | 非法会话编号（含斜杠、双点）不产生越界写入。 | 单测 |
| AC-10 | 不激活任何层时，系统提示词段仍为空串（零 token）。 | 单测 |
| AC-11 | 第 4 条仍被拒绝（layer-limit），层数仍为 3。 | 单测 |
| AC-12 | 现有测试仍全绿；新增测试覆盖 AC-1..AC-11、AC-13、AC-14。 | npm run check |
| AC-13 | 文件不存在/格式错/字段错/超大/不可读/读取中被删：备份/兜底可读时自动恢复；都失败时会话加载与无文件时一致，侧边栏正常，无抛错、无写盘；超过 1 MiB 的文件不被读取解析；I/O 类失败且所有副本都不可用时的加层被拒绝、磁盘文件不变；混合情形按 I/O 优先；内容类失败无副本且无 I/O 错误时允许加层覆盖坏主文件。 | 单测 + 手工 |
| AC-14 | 单会话首次读取新增耗时 p95 ≤ 100ms、典型 ≤ 20ms；重复读取只 stat、不重复解析；不扫描全部会话。主判据是“10 MiB 不读取 / 重复只 stat / 坏主文件不重复解析”的机械断言；p95 是设计预算，计时只作手工烟雾测试。 | 机械断言 + 手工计时 |

## 7. 约束与依赖

- **平台目录布局**：层文件放在 DSH 的会话目录（$DSH_HOME/sessions/项目/会话 id/）。DSH 平台源码注释把该目录称为“available for future session-local artifacts”，且它的目录扫描只识别 session.v版本.jsonl.zstd 这类日志文件，不认识的文件会跳过。详见设计档 §1.3。
- **不与其他插件耦合**：本插件只约定“文件在会话目录、能从会话目录加载”；文件如何被外部搬移、复制、同步，不在本批范围。
- **重启规则**：改 host 代码需要重启 DSH 才生效。按用户规矩，重启前先报告在跑的会话/作业与影响，由用户决定时机。
- **读路径零写**：读失败不隔离、不改名、不清理、不写盘；只有用户显式加/删层才写。
- **大小上限**：单文件超过 1 MiB 不读取、不解析，直接按无层处理；有效文件远小于这个上限。
- **本地文件假设**：DSH_HOME 在本地文件系统；本批不做网络文件系统上的阻塞超时承诺。
- **数据边界**：本批不实现层文件的导出/导入；换机后需要重新加层。
- **本地优先**：不联网、不上传；文件可手工查看/删除。

## 8. 决策记录（2026-10-29）

- 存储位置：文件放进会话自己的文件夹；本插件只负责这一处的读写，不与其他插件耦合（用户选定）。
- 重启行为：自动恢复注入；用户不想要时自己点 ×（用户接受继续计费）。
- 可见性：不加“已恢复”标记、不新增开关（用户明确“chip 自身就是提示”）。
- 流程：先出需求档 + 设计档；用户看过并发起独立评审；评审通过后走工程模式实施。
- 上限：保持最多 3 条不变。
- 失败分类（2026-10-29 评审裁定）：I/O 类（stat/read 异常、不可读、读取中被删）且所有副本都不可用 → 拒绝写入（layer-read-failed）；混合情形按 I/O 优先（只要出现过 I/O 错误且无可用命中就拒绝写入）；内容类（格式/字段/超大/非普通文件）且无可用备份/兜底、且没有任何 I/O 错误 → 允许加层写新文件覆盖坏主文件（修复）；非普通文件写入被文件系统拒绝时返回 layer-persist；有可读副本时按副本继续。

## 10. 脱敏与入库

- docs/ 下的需求/设计文档（0.1 + 0.2）在脱敏后纳入 Git：从 .gitignore 移除 docs/，先确认全部 docs/ 扫描零命中，只提交 docs/ 与 .gitignore 的相关改动。
- 入库时机（2026-10-29 用户裁决）：等设计评审通过、进入实施阶段再执行；本轮只做脱敏，不改 .gitignore、不提交。
- 脱敏规则：路径用 $DSH_HOME 占位；示例会话 id 用合成值；不写用户名、本机绝对路径、其他插件仓库路径。
- 提交前检查：搜索用户名、盘符、真实会话 id；docs/ 下所有文档必须零命中。
- 文档里的平台包路径（如 dsh-session-persistence-jsonl/lib/index.js）是依赖包路径，不是本机目录，可保留。
