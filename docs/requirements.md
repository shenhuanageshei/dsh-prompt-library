# dsh-prompt-library 需求档

> 三句话：把常用长提示词存成一个本地库，在会话里用 `/` 选、先改后发；
> 默认只进普通上下文，需要更高优先级时再叠加到本会话的系统提示词末尾；
> 不用的时侯零 token 成本，不学 AGENTS.md / dsh-prompt-layer 的全局常驻注入。
>
> **0.2 增量**：系统层已改为**按会话持久化**（写在该会话自己的目录里，重启/刷新后自动读回）。本档描述 0.1 行为的地方已按 0.2 回写；0.2 的事实源是 [2026-10-29-session-layer-persistence-requirements.md](2026-10-29-session-layer-persistence-requirements.md) 与 [2026-10-29-session-layer-persistence-design.md](2026-10-29-session-layer-persistence-design.md)，两者冲突时以 0.2 档为准。

## 1. 背景

- 用户有 3 条以上常用长提示词（极限测试授权、自主推进授权、说人话），目前靠手工复制粘贴。
- 现有可选做法都有明显代价：
  - 写进 `AGENTS.md`：每个会话、每次请求都占 token，不用也付费。
  - 装 `dsh-prompt-layer`：把配置里一段固定文字常驻到系统提示词，同样全局计费，且没有库、没有选择、没有会话范围。
  - 临时粘贴：易错、难管理、无法复用。
- DSH 原生已有 `/` 触发器、可动态返回空文本的系统提示词段、输入框上方 dock、设置页插槽、Remote 通道；插件不需要魔改。

## 2. 用户与场景

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| S1 | 单条插入 | `/` 里选一条，编辑确认后进输入框，发送前还能改 |
| S2 | 两条进普通上下文 | 连续选两次，两条正文都在输入框里，顺序可改 |
| S3 | 会话级系统层 | 选一条（或两条）注入系统提示词末尾，顶部 chip 显示，可单独关 |
| S4 | 混合 | 一条插入输入框 + 一条系统层，两边同时生效 |
| S5 | 管理 | 设置页增删改查、标签、排序、导入导出、token 估算 |
| S6 | 重启 | 提示词库保留；系统层从该会话自己的目录读回，chip 与系统提示词段一起恢复（0.2；0.1 为清空）。不想要时自己点 chip 上的 × |
| S7 | 多会话 | 每个会话有自己的系统层；库是全局的 |

## 3. 功能需求

### P0（v0.1 必须）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-1 | 提示词库 CRUD | 全局 JSON 文件；id / 标题 / 正文 / 标签 / 时间；原子写 + 备份 |
| FR-2 | `/` 菜单入口 | 输入触发源，组名「提示词」，放在最前；按标题/标签/正文过滤 |
| FR-3 | 编辑确认弹窗 | 每次选中先弹窗；正文可改；默认「插入输入框」，可切「注入系统提示词」 |
| FR-4 | 普通上下文插入 | 在光标处替换 `/查询` token，不吞前后文字；连续选两次可叠加 |
| FR-5 | 系统层可叠 | 最多 3 条；每条一个 chip；同 id 重复添加视为更新；显示总 token |
| FR-6 | chip 管理 | 每条可单独 ×；点标题可重新编辑该层正文；系统层按会话持久化到该会话自己的目录（0.2；0.1 仅存进程内存） |
| FR-7 | 设置页 | 列表/搜索/新增/编辑/删除/导入/导出；显示每条 token 估算 |
| FR-8 | 文案与主题 | 中文默认、英文可选；跟随 DSH 亮/暗主题 |
| FR-9 | token 估算 | 中文按约 0.75 token/字，其他按约 0.28；弹窗与 chip 都显示 |
| FR-10 | 失败边界 | 库文件损坏不阻塞启动；备份后空库；写入失败回滚并提示 |

### P1（v0.2 候选）

- 全局快捷键（Ctrl+Shift+P）打开选择器，可在快捷键设置里改。
- 从当前输入框内容一键保存为提示词。
- 按工作区分组（workspace scope）。
- 排序拖拽、批量导入。
- 右键菜单（无原生插槽，只能 DOM hack，风险高，暂不做）。

## 4. 非目标

- 不做全局常驻注入：没有激活的系统层时，系统提示词零新增 token。
- 不做模型自动推荐提示词。
- 不做云同步/团队共享（库是本地文件）。
- v0.1 不做模板变量（{{cwd}} 等）、右键菜单、提示词版本历史。
- ~~系统层不持久化到磁盘：DSH 重启即清空，避免“看不见的持续计费”。~~ **0.2 已废止**：用户裁决改为按会话持久化，重启后自动恢复注入并继续每轮计费；不想要时自己点 chip 上的 ×（见 0.2 需求档 §8 决策记录）。

## 5. 验收标准

| 编号 | 验收点 | 检查方式 |
| --- | --- | --- |
| AC-1 | 空库时 `/` 菜单仍正常，提示词组不出现 | 手工 |
| AC-2 | 选中一条，编辑后插入，输入框内容 = 编辑后的正文，菜单位置被替换 | 手工 + DOM 断言 |
| AC-3 | 连续选两条，输入框同时有两条正文，可删改 | 手工 |
| AC-4 | 系统层叠加两条，chip 显示 2 条 + 总 token；系统提示词含两段正文 | 手工 + 系统段检查 |
| AC-5 | 第 4 条被拒绝，提示“最多 3 条” | 手工 |
| AC-6 | 关掉其中一条 chip，只剩另一条；系统段同步变短 | 手工 |
| AC-7 | 重启 DSH：库仍在；系统层 chip 与该会话的层一起恢复（0.2；0.1 为全部消失） | 手工 + 0.2 单测（layer-store 新实例读回、空状态写回） |
| AC-8 | 损坏 prompts.json：能启动，坏文件被改名备份，库为空并提示 | 单测 + 手工 |
| AC-9 | 设置页增删改查后重启仍在 | 手工 |
| AC-10 | 亮/暗主题下可读；无硬编码颜色 | 目测 |
| AC-11 | 不激活系统层时，系统提示词没有新增段落（section 返回空串） | 单测 |
| AC-12 | 任何操作不产生模型消息（只有用户最后发送的那条） | 手工 + 日志 |

## 6. 约束

- 纯本地：不联网、不上传；库文件可手工编辑、进 Git。
- 运行环境：DSH 0.2.x（当前 0.2.1-rc.2）+ Web 客户端；Windows 优先，兼容 macOS/Linux。
- 插件形态：本地 bundle 插件（host + client 双 half），挂在 desktop profile。
- 安装/升级需要重启 DSH；按用户规矩，重启前先报影响（在跑的会话/作业）并等确认。
